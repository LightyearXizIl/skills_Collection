# 实战踩坑库（追加式，只增不删）

来源：2026-09-22 ~ 09-23 一套产品实拍图（透明壳 + 环支架手机壳）的精修/重渲染全流程实战。

---

## 1. 重渲染会破坏什么（按出现频次排序）

| # | 破坏方式 | 现象 | 设防写法 |
|---|---|---|---|
| 1 | **抹除 LOGO / 丝印** | 机身上的微弱 LOGO 被当污渍擦掉 | `REMOVE` 段加 `EXPLICIT EXCEPTION`；正文写 "NOT dust / smudge / scratch / noise" |
| 2 | **LOGO 移位 / 重新居中** | 被摆到环内孔正中、变成完整可见，遮挡关系丢失 | **位置条款写在可见性之前**；明写"偏下部、被环带下段重叠""禁止居于中部上部""禁止在孔内完整可见" |
| 3 | **LOGO 提亮 / 放大** | 微弱 LOGO 被修成清晰白标 | 写"不得比原图更可见 / 更大 / 更锐 / 更亮"；`AVOID` 用全大写 |
| 4 | **字标退化**（Λ → A） | 品牌变体字被打回常规拼写 | 逐字符列位次 + 字形描述 + 禁止规范化 + 失败判据（见 `03`） |
| 5 | **构件被合并** | 壳的凸起边框与机身平台合成一块平板，阶数丢失 | 明写"属壳体、与平台为两件、共 N 阶" |
| 6 | **断口被补成闭合** | 开口环变成完整圆环 | 明写"断口 N 处、位于自身某侧 / 画面约几点钟" |
| 7 | **构件被补画出来** | 屏幕面视角里凭空出现背面摄像头 / 环支架 | 明写"某一面朝下、本视角不可见"，并禁止翻转 |
| 8 | **屏幕被点亮** | 熄屏被修成有壁纸 / 状态栏 | `the screen MUST stay switched off: … no UI of any kind` |
| 9 | **印刷内容被"扶正"** | 画面中倒置的文字被转正、重排 | `keep it IN ITS ORIGINAL ORIENTATION — do not rotate it upright` |
| 10 | **表面被磨平** | "去噪"被执行成"抹掉拉丝颗粒 / 扩散件晶格 / 织物织纹" | 补 `do NOT interpret "smooth / clean / no noise" as permission to erase real surface micro-grain` |
| 11 | **素材被修成浅绿发亮** | "AR 镀膜反射"条款被过度执行 | 写 `the glass stays DARK, the AR tint must remain subtle`；`AVOID` 加 `light, bright, milky or saturated green lens glass` |
| 12 | **倒影被编造 / 镜像背景** | 光面反射里出现凭空物体，或把背景道具镜像进去 | `keep a real reflection PRESENT` + `do NOT invent … and do NOT mirror the background props into it` |
| 13 | **背景光斑被抹平** | 拉高对比时优先牺牲高频亮斑 | 光斑列为硬保留项（形状 / 边缘 / 位置 / 柔度全不动） |
| 14 | **包装盒文字被改写 / 补全** | 被裁切的字标被"补全"、无法辨认的小字被锐化成另一组词 | 盒面全部文字、字标、徽标、配色入 `MUST PRESERVE`；`AVOID` 加 `rewriting or completing illegible box text` |

## 2. "材质修不好"的根因排查（按顺序查）

1. **先查任务类型，不是影调参数**：提示词里是否有 `not a re-render` / `not a synthetic render` / `keep it a real photo`？有 → 删除，并把任务升级为**产品区域重渲染**。
2. **再查材质段是否逐面**：只写"提升质感 / 加清晰度"必然偏平；必须逐面给 PBR（粗糙度倾向 / 镜面响应 / 高光宽度 / 反射连续性 / 表面纹理 / 透明关系）。
3. **再查影调段**：`ENHANCE` 要写"黑端压深 + 白端提亮"，同时补两条闸——`NO grey haze lift`（防灰雾）与 `never clipped detail-less dead blacks`（防死黑）。
4. **最后查验收项**：出图后按项验，不要凭整体感觉判断。

## 3. 文档维护陷阱

### 批量字符串替换的子串重叠

- 事故：把 `ASY → ΛSY` 全量替换时，提示词里**用于标注错误拼写的 `MAGEASY`** 也被改成 `MAGEΛSY`（因为 `MAGEASY` 内含 `ASY` 子串）。
- 规则：**做全量替换前，先排查目标串是否为其他词的子串**；对"反面示例文本"（如"不得写成 X"里的 X）应改用**逐处定向替换**，或替换后再逐处复核。
- 同理：改品牌拼写时，文件里通常同时存在**正确拼写**与**反面示例拼写**，二者语义相反，不可一律替换。

### 文件版本堆积

- 同一图片反复迭代时，**每轮只改被要求的部分**；旧版本文件不要留在主目录，移入 `_backup_*`。
- 每次交付声明"哪份是唯一权威版本"，避免用户从旧文件复制。

## 4. 交付口径（用户明确过的偏好）

- 先给**结构化锁定清单**，再给**一键复制提示词**；提示词必须在代码块里。
- 提示词只输出文字，**不自动生成图片**。
- 每轮改动给出**对照表**（本版 vs 上一版），并列出**出图后优先检查的 2–4 项**。
- 结构锁定项一旦被更正，**必须显式告知**（静默修正会让用户继续用错版本）。
- 需求侧决策（背景 / 手 / 倒影）**给出默认值 + 可切换项**，不擅自替用户决定，也不反复追问。
- **成品尺寸 = 精修图尺寸**（不要压回原图分辨率）。
- 用户会直接拿成品放大看细节（"你自己看能用吗？"）——**交付前自己先放大关键区域验收**，不要等用户发现。
- 结构类判断出错时，**要自我修正并说明**（如"本图看不到 LOGO"被实拍图推翻），不要含糊过去。
- **每张图必须带「原图尾号 4 位」**（2026-09-23 用户原话："提示词你要把原图尾号4位写上，不然我不认识"）。
  本项目原图一律叫 `canvas-image-<随机串>.png`，**前缀相同、只有末尾可区分**；用户在自己的工具里看到的就是文件名末尾，
  所以只写「图①/图②/图③」他无法对应到具体文件。
  **尾号 4 位 = 文件名去扩展名后的最后 4 个字符**（`canvas-image-_zPAle-ZZ-y_gbSEnnMOu.png` → **`nMOu`**）。
  落笔位置：提示词**小节标题**、文件开头的**图片对照表**、回贴命令的 `--out`（`<尾号>_成品.png`）。
  另需一份跨批次的 `原图尾号4位对照索引.md`。
- **尾号会变，必须重扫文件夹，不能沿用上一次的尾号**（2026-09-23 实测踩到）：
  用户把同一场景的文件**从 1086×1448 换成 4K 原生版**后，**文件名整体变了**
  （`nMOu/ThUD/kGVu` → `gZm3/N7Za/e-sd`），旧的尾号与旧坐标同时作废。
  → 每次用户给目录/说"给你"，**先 `ls` + 读尺寸，再核对尾号是否仍对得上**；
  → 尺寸一变，**环心/半径必须从新图重测**，不要用"同比换算"蒙（本例缩放比 x/y 就不相等：3.3002 vs 3.3149）。

## 5. 字标 / LOGO 无法靠提示词保真（本项目最贵的一课）

- 症状：用户连续三轮反馈——"LOGO 被修没了"→"位置不对，应该是被遮挡的"→"**苹果 logo 和 MΛGEΛSY 不要重绘，保持原图，现在出的图没法用**"。
- 根因链（每修一层暴露下一层，说明**问题层级在任务类型而非措辞**）：
  1. 去瑕逻辑把微弱 LOGO 当污渍擦掉 → 加 `EXPLICIT EXCEPTION` 豁免；
  2. 反向禁令"不得编造 LOGO"被读成"本图无 LOGO" → 收窄为"只禁新增"；
  3. 模型把 LOGO **重新居中**到最好看的位置 → 加"位置条款先于可见性"；
  4. 字标 `MΛGEΛSY` 被模型按常规拼写改成 `MAGEASY` → 加逐字符锁定 + 失败判据。
  **但这些都只是把损失降到最低——只要经过"重绘"，精细字标就不可能逐像素保真。**
- **正解（两步法）**：
  1. 提示词里加 `PROTECTED REGIONS` 排除区：把字标与 LOGO 声明为"如同编辑前就被挖掉"，区域内输出必须与原图一致，无法保证则原样保留；
  2. **出图后用 `scripts/restore_regions.py` 把这两个区域的原像素贴回**（`--annulus` 贴环带上的弧形字标，`--circle` 贴环内孔里的 LOGO，`--feather` 羽化过渡）。
- 交付纪律：凡提示词含 `PROTECTED REGIONS`，**必须同时给出回贴命令**，并明确告诉用户"最终保真靠回贴这一步"。只给提示词而不给回贴步骤，等于把问题留给用户。
- 通用化：**凡"精细文字、小字、认证标、弧形排版字"参与重绘，一律走两步法**；不要指望模型逐字准确。

## 6. 环定位：从"不可靠"到"可用"（算法修正记录）

**第一次尝试（失败）**：用「环带均值 − 内孔均值 − 环外均值」的圆盘打分自动找环。
- 现象：先锁到孔内的小亮斑；加尺度权重后锁到"大圆吃掉亮桌面"；加裕度约束后仍偏心；圆周一致性只有 0.26–0.52。
- 根因：**光面机身背面有大面积室内反光**，"亮环 + 暗底"的前提不成立；圆盘/环带的**区域均值**对偏心极不敏感。

**第二次尝试（成功）**：改为只用两条圆周的边缘强度，且内缘半径独立搜索。
- 评分：`外缘圆周梯度均值 + 内缘圆周梯度均值`（梯度取 3×3 邻域最大值，容忍 1px 圆不完美与轻微透视）；
- **内缘半径独立搜索**，不按固定比例（环带厚度随机位变化：本项目 r_in/r_out ≈ 0.67，而旧版写死 0.60）；
- **限定搜索范围**到环的实际尺度（按图宽比例给 `--cx-range / --cy-range / --r-range`），这是能收敛的关键前提；
- 两张图独立拟合后交叉验证：原图 (854,635) r_out=162 → 映射到精修图尺度 (1132,838) r≈214；精修图独立拟合 (1133,840) r_out=214。**Δ≈1–3px，互相吻合**，同时证明两图只是纯等比缩放（后续坐标可直接复用）。
- 落地：`scripts/locate_ring.py` 重写为本算法，**强制输出叠加预览 + 双缘强度 + 置信度告警**，并支持 `--verify-with` 交叉验证。
- 通用化：**凡是"自动测量"类工具，必须自带可复核的可视化产物与置信度指标**；并且**搜索范围要按物理尺度约束**——无约束的自动搜索在实拍图这种强反光、低对比场景里等于赌博。

## 7. 成品尺寸与贴回接缝（用户明确要求）

### 尺寸：以精修图为准

- 事故：回贴时用了 `--match source`（输出压回原图 1448×1086），用户直接反馈"**尺寸要精修后的尺寸**"。
- 规则：**交付成品的分辨率以精修图（nano-banana-pro 输出，通常是 1920px 级）为准**，回贴用 `--match edited`。原图会被等比放大后贴回——字标区域因此略软，但这是拿保真换分辨率的必然结果，要在交付时讲清。
- 注意：坐标要填在**输出画布**的坐标系里。`--match edited` 就填精修图坐标；若换了机位或分辨率，坐标必须重算。

### 接缝：羽化就够，别急着做色调匹配

- 实测数据（本项目图）：贴回边界上「原图 vs 精修图」的平均亮度差仅约 4 级（外侧扩大到 ~10 级），**边界本身的台阶很小**。
- 处理：`--feather 16` 即可。用「边界环带梯度能量 ÷ 内外邻带梯度能量」度量，实测比值 **0.14**（< 1.2 视为不可见）——即边界处比周围还平滑，无可见接缝。
- 让边界落在**环外的暗部**（半径留 6–10% 余量），不要切在金属环上：切在强边缘上反而容易被"看到"；切在平坦暗部 + 羽化则彻底看不出来。
- `--level-match` **慎用**：本项目实测该邻域"暗部几乎一样（26→27）、亮部差很多（76→55）"，按分位点对齐会得到斜率 ~0.58 的色调压缩，**把明亮金属环整体压暗**（金属环失去刚复原的亮度）。默认不加，除非接缝肉眼看得到且两图影调差距确实很大。
- 通用化：**修复合成的优先级是「把边界放到感知不敏感的位置」＞「羽化平滑」＞「色调匹配」**。色调匹配会改变贴回区（也就是我们要保真的那个区域）的影调，是有代价的最后手段。

## 8. 空壳场景 vs 装机体场景：环内孔里该看见什么（2026-09-23 新一批图）

同一产品的实拍图会分两类，**判定错就会凭空造物**：

| 场景 | 壳内 | 环内孔里本该看见 | 第一禁令 |
|---|---|---|---|
| **装机体**（先前的图） | 有手机 | **机身背面 + 被环带压住一半的苹果 LOGO** | 不得把 LOGO 修没 / 移位 / 提亮 |
| **空壳**（本批三图） | 无手机 | **壳背磨砂面 / 盒内衬 / 背景毛毯** | **不得往壳里补一部手机、不得往环内孔补 LOGO / 镜头 / 金属片** |

- **做法**：锁定清单里**单列一条**「壳内是否装着手机」；环内孔的可见内容按"只锁外观事实、不判它是什么"处理（本批连"是壳背板还是盒内衬"都无法从单视图区分）。
- **通用化**：**"产品先验"是双向陷阱**——模型知道这是手机壳，装机体图上会自己补 LOGO，空壳图上则会自己"补一部手机进去"。凡是"本该有 / 本该没有"的判断，都要在提示词里明写，不能留给模型。

## 9. 圆形装饰物会把自动定位带偏（实测复发两次）

- `locate_ring.py` 在图①上**锁到了包装盒上的蓝色圆形"360°"贴纸**（该贴纸是"亮圆 + 暗底"，完全符合算法偏好），叠加预览一眼可见错误。
- 处理：
  1. **必须限定搜索范围**（`--cx-range / --cy-range / --r-range`）把画面里的圆形装饰物排除在外；
  2. **叠加预览是强制步骤**，不看预览就把坐标当结果，等于赌博（本批就是靠预览否决了第一次结果）；
  3. 换范围重跑即得到正确结果（图① 环心 (517,686)、外半径 156）。
- **通用化**：画面里的**圆形贴纸、圆形徽标、镜头、圆形标签**都是环形检测的强干扰项；搜索范围要先按"产品实际占位"框住，再谈精度。

## 10. 微距 / 透视下的环是椭圆，圆拟合不可用

- 图③ 是环体微距，且略带侧视 → 环在画面里**被压成椭圆**（实测横/纵半径差约 7–8%）。用圆拟合会得到"中心偏移上百像素"的假结果。
- 有效做法（本批实测）：
  1. 先用**椭圆边缘拟合**找到内孔边界（`Σ 椭圆圆周上的梯度均值`最大化）→ 得到 (cx, cy, a_in, b_in)；
  2. 再**以内孔椭圆为基准，沿"椭圆族"向外找金属亮区的最外侧边界**（用**亮度阈值**而不是梯度——梯度会锁在环带内部的刻线上），取各角度的中位缩放比 → 外椭圆；
  3. 回贴用 `restore_regions.py --ellipse cx,cy,ax,ay`（新增参数，ax/ay 是半轴）。
- 图③ 实测：内孔椭圆 (720,764,326,290) → 外椭圆 (720,745,430,400) → 回贴用 `--ellipse 720,745,447,416`（外扩 4%，边界落在环外暗部）。
- **通用化**：**先判形状再选模型**——近正圆用圆，微距/斜视用椭圆；不要拿圆的公式去套椭圆的目标，也别反着来。
- **2026-09-23 补充：椭圆还会「歪」，轴对齐椭圆同样套不住。**
  星云批次图③ 是**手持 + 明显倾角**，环外缘实测是**旋转椭圆**（半轴 560/775、**倾斜 −16°**）。
  轴对齐椭圆的包围盒版本（613×806）能把整个环包住，但四角白贴回一大片手机壳表面，
  等于把那块区域的精修效果整个撤销；而按包围盒「刚好」缩小，又必然有一个角露在椭圆外——
  **露出去的那一角就会被模型重绘，字标照样毁**。
  → `restore_regions.py` 已支持旋转：`--ellipse cx,cy,ax,ay,angle`（第 5 个数＝角度，度，逆时针为正），
  `--annulus` 同样支持第 5 个角度参数。
  → 拟合方法（实测可靠）：在**环带颜色掩膜**（品红/紫：`B−G>14 且 R−G>8`）上做**网格搜索**，
  目标＝在覆盖率 ≥99.9% 的前提下取面积最小；再画**叠加预览人眼复核**一轮。
  图③ 最终 `--ellipse 2235,2930,593,821,-16`。

## 11. 素材分辨率：别用对话里收到的那份图（2026-09-23 实测）

- 用户说"我是出的 4K"。对话里收到的三张是 **1433×1920**，而磁盘上的真实成图是 **3584×4800**——**上传/粘贴环节会把图压小**。
- 后果：若按对话里那份做回贴，交付分辨率就被默默降级了（用户要 4K，你给 1920）。
- 做法：**向用户要素材目录，从磁盘直接读**（`E:\...\成品\银白\黑色毛绒地毯\canvas-image-*.png` 这类路径），再按真实尺寸重算坐标：
  - 坐标换算：新尺寸 = 旧尺寸 × 比例（本例 3584/1433 = 4800/1920 = **正好 2.5×**）；
  - 换算后**必须复核**：跑一次 `locate_ring.py` 或用 1:1 裁剪比对，确认环心/半径吻合（本例实测 683,912/r207 → 预测 1708,2280/r517.5，一致）；
  - `--feather` 也要按比例放大（16 → 40），**但掩膜必须同步外扩**——羽化是绝对像素，
    只放大羽化而不给掩膜留出 `2×feather + 20px` 的余量，过渡带就会压在物体边缘上产生重影（详见 §16.1）。
- **大幅放大必配锐度补偿**：原图只有 1086px，贴回 4K 要放大 3.3× → 贴回区会明显比周围软。`--sharpen-amount 80 --sharpen-radius 2 --sharpen-threshold 4` 把边缘锐度提到与周围相当（只改锐度，不改字形与位置）。
- **贴回范围要收窄**：只贴最脆弱的（环上那串淡字）。**大号清晰的印刷字模型通常保得住**——本例 4K 盒面文字（BRIGHT 360° / Built-in Magnet / Enhanced Wireless Charging / New Function Compatible / For 2026 iPhone Pro Max / 16FT | 4.8m / Open Here）逐条放大核对无误，**因此没有把盒面整块贴回**——否则那一大片会被 3.3× 放大后拖软，得不偿失。
- 通用化：**先把"交付分辨率"和"素材分辨率"两个数对齐**，再谈坐标与贴回；错在这一步，后面都白做。

## 12. 事实类判断：先放大/取样，再下结论（2026-09-23 两次误判的教训）

本会话里我犯过两次"凭低倍率印象下结论"的错，都造成了返工与撤回：

| 误判 | 当时的依据 | 实测后 |
|---|---|---|
| 环支架是**紫色（深紫罗兰）** | 看整图时的颜色印象 | **银白**（暖阳下略暖，取样 RGB ≈ 204,198,183） |
| 盒面大字第 2 位是**带横杠的 A** | 4K 截图下的主观判断 | 同一字标放大到 5× 逐字辨认，**是无横杠的 Λ**（`MΛGEΛSY`） |

**规则**：
1. **字形争议 → 局部放大到能逐字辨认（经验值 ≥5×）再判定**，并在交付里写明"依据是哪张图、放大多少倍"；看不清就写"无法确认"，**不要用"看起来像"下结论**（§S-8 的拼写纪律也依赖这一点）。
2. **颜色争议 → 像素取样读 RGB**（在避开花字与高光的区域取中位数），不要凭整图观感描述颜色。
3. 这两类事实一旦写进提示词或锁定清单，就会被当成权威；**错一次要撤回一轮**，成本高于多花 30 秒核验。
4. **自我修正要显式**：发现前期判断有误时，在交付中写明"此前说法作废 + 实测结论"，不要静默改口（用户会继续沿用旧结论）。
5. **但更正别矫枉过正**：本会话就出现过"把个别误判扩大成通则"——因为某张图里环是银白，就把整条"紫色环"判为误判；随后下一批（`星云` 配色）**真的是深紫环**。**结论要带适用范围**（"这一张是银白" ≠ "这个产品只有银白"）。

## 13. 配色属于"可变项"，而且是模型最爱"修正"的东西

- 同一产品线的**配色 SKU**（银白 / 星云 / 墨岩 / 迷雾…）会带来**环支架、按键罩等件的颜色差异**：银白配色 → 银色环；星云配色 → **深紫罗兰阳极氧化环**。
- 锁定纪律：
  1. **配色按批次（配色）各自锁定**，不跨批套用、不因配色差异判为"不同版本"（结构仍通用）；
  2. 提示词里必须**正面写清颜色本身**（`a DEEP PURPLE / VIOLET ANODIZED aluminium annulus`），并给该色的**材质响应**（阳极氧化 + 细同心圆拉丝 + 机加工亮倒角）；
  3. `AVOID` 里用**全大写 + 穷举**禁止改色：`recolouring the purple ring to silver / chrome / grey / black / gold`。实测模型有很强先验会把"非典型"的紫环**改成常规银色**，以及把**两枚淡绿镀膜镜头改成深色/统一成一样**。
- 同类"容易被顺手改掉"的还有：**镜头玻璃的镀膜色**（本批两枚淡鼠尾草绿 + 一枚深色，且**随机位变化**）、**按键罩颜色**（与环同色系）。凡"实物与常规不同"的颜色，都要正面写死 + 双向禁止改动。

## 14. 画面里有手 / 皮肤 / 美甲时的锁定纪律

- 只要画面含手（本批三张都是手持或露手），必须在 `HARD SCENE LOCK` 里写：
  - 手是**场景**不是修图对象：**禁美化、禁瘦手、禁磨皮、禁改指甲、禁增删手指、禁移动手指**；

## 15. 环几何测量：三个"看起来对的错答案"（2026-09-23 灰白水磨石台批次）

同一批两张图，测量环节连着踩了三次坑，**每一个都产出"数值合理但实际错"的结果**。按顺序记：

### 15.1 中心别用"质心迭代"——它会漂到别的小簇上

- 做法：`cx,cy = mean(所有紫像素)` → 按 `[0.6R,1.4R]` 收窄 → 重算均值，迭代几轮。
- 现象：`BcL-` 收敛到 `(476,608) R=46`（真值应为 `(617,617) R≈151`）——**完全跑到另一个小簇上**。
- 原因：掩膜里除环带外还有零星紫色簇，**质心对簇的"质量分布"敏感**；一旦某轮把主环排除在外，就再也回不来。
- **正确做法**：用**代数圆拟合（Kåsa）**求中心——解一个 2×2 线性方程组，输出对离群点稳健得多。
  同一掩膜下 Kåsa 直接给出 `BcL- (617,617) R=151`、`GSAK (623,636) R=145`，与叠加预览吻合。
- 通用化：**初值/中心这类"全局量"要用全局拟合，不要用质心迭代**；质心迭代只适合"已知就一个连通块"的干净掩膜。

### 15.2 Kåsa 的 R 是"环带中位半径"，**不能当回贴半径**

- `R=151` 是**环带像素径向分布的中位数**（≈ 环带中部），而**回贴要的是外缘**。
- `BcL-` 实测外缘 ≈ **172–175**，比 `R=151` 大 15%。**直接用 R 会把环带外圈那一截留在保护区外** → 那圈被模型重绘，字标弧段的首尾首当其冲。
- 通用化：**"拟合出的半径"必须先确认它代表哪条边界**（中位/内缘/外缘），再乘余量；不确定就看叠加图。

### 15.3 椭圆拟合别用 Fitzgibbon 直接法（在本环境里会崩成复数）

- 用"直接最小二乘椭圆拟合"（广义特征值）→ 输出**复数**（`474-0j`、`46×25`），并抛一串 `ComplexWarning`；`BcL-` 得到 `ax=46` 的垃圾椭圆。
- **改用稳健轮廓法（实测可靠，纯 numpy 即可）**：
  1. Kåsa 定中心 → 算 `r=hypot(x-cx, y-cy)`、`ang=atan2`；
  2. **按角度分箱（720 箱）取每箱 r 的 95 分位** → 外缘轮廓 `rbin`（分箱比"整体极值"抗离群）；
  3. 空箱线性插值 → **裁剪到 `[0.72,1.30]×median`** → **圆周中值滤波（窗 25）**；
  4. 轮廓点做**主轴投影**：长轴 `a=(max−min)/2`、短轴 `b=(max−min)/2`、`angle=atan2(主轴)`；
  5. 回贴用 `--ellipse cx,cy,a×1.05,b×1.05,angle`。
- 结果：`BcL-` `(612,620) ax172 ay175`（≈正圆，用 `--circle 612,620,180`）；`GSAK` `(625,634) ax182 ay131 176.3°`（≈轴对齐，倾角 −4°）。

### 15.4 两个收尾自检（不靠肉眼也能判对错）

- **归一化半径覆盖率**：把环带像素投到椭圆坐标系，算 `rho=sqrt((u/a)²+(v/b)²)`。
  **判据：`rho≤1.04` 的占比 ≥ 96%**。本批 `BcL-` 98.7%、`GSAK` 96.6% 通过。
  （`rho` 的 p95 若远大于 1，说明椭圆比环带小 → 必然漏角。）
- **回贴掩膜端到端校验**：造一张 `invert(原图)` 当 edited，跑 `restore_regions.py`，
  再比较输出中"等于原图"的像素集与**解析椭圆掩膜**的 **IoU**（本项目实测 **0.987**，证明脚本的角度约定与手写公式一致）。
  这个方法能在不读图的情况下验证"角度符号 / 旋转方向"这类最容易搞反的参数。

- 通用化：**测量管线每一步都要有可判定的量化自检**（覆盖率、IoU、离散度），因为"叠加预览看着差不多"最容易放过多 15% 的半径误差。

## 16. 出图被放大时：掩膜必须外扩，否则羽化带会压在环边（2026-09-23 首次真机回贴）

用户拿提示词跑出图后，**nano-banana-pro 把 1254×1254 的原图放大成了 4096×4096**（比例 3.266）。这次是第一次"真机回贴"，暴露了两个新问题。

### 16.1 致命错误：羽化带压在环的外缘上 → 双环重影

- 我的做法：坐标同比换算（`612,620,180 × 3.266 → 1999,2025,588`）+ **羽化也同比放大（16 → 52）**，理由来自 §11 的"`--feather` 要按比例放大"。
- 现象：成品里环的外缘出现**重影 / 双环**——原图环边与生成图环边各占 50% 叠在一起。
- 根因：**掩膜半径 588 ≈ 环外缘半径（实测 595）**，而 `--feather 52` 的过渡带跨度约 ±2F = ±104，
  于是过渡带 `[484, 692]` **整段压在环体与环边上**。掩膜边缘 = 羽化的 50% 点，
  落在环外缘上 → 环边被两图各掺一半。
- **正确规则（写死）**：

  ```
  mask_edge ≥ 环外缘 + (2×feather + 15~20px 安全量)
  ```

  即**羽化越宽，掩膜越要往外让**；目标是把整条过渡带推到环的剪影**之外**（落在环边的暗部 / 玻璃接触阴影里，那里两图都接近黑，接缝天然不可见）。
- 本次修正：`--circle 1999,2025,588 → 643`（外扩 55），`--feather 52 → 16`；
  `--ellipse …,624,451 → 679,506`。修正后过渡带 `[611,675]` 完全在环外（环外缘 595）→ 重影消失。
- **通用化**：**"按比例放大羽化"只在掩膜也同步外扩时才成立**。放大倍率越大，掩膜相对物体剪影越要往外让——
  因为羽化是**绝对像素**，环的剪影也是按比例变的，两者必须一起算，不能只乘羽化。

### 16.2 别用紫环**质心**判断对齐——它会骗你 100px

- 我一度以为生成图取景漂了：紫掩膜质心「生成图 (1937,2059) vs 原图 (1812,1979)」→ 差 (125,81)，看起来像位移。
- 实测：**环其实完全对齐**。射线扫外缘（从中点向 360 方向取最外侧紫像素）显示
  `BcL-` 生成 `ax/ay=597/547` vs 原图 `595/545`、`GSAK` `625/460` vs `624/461`，
  **中位差仅 ±1~3px**；四个正方向（上/下/左/右上）甚至逐位相等。
- 质心为什么骗人：阳极氧化环的**镜面高光把紫掩膜打得粉碎**（最大连通域只占全部紫像素的 **3%**），
  再加上生成图的紫色区域比原图**多 60~80%**（CGI 紫更饱和 / 更宽），质心被"质量分布"拉偏。
  同理，**并集外接框也不可信**：本次被污染块撑到 `ay=588`（真值 460），照它定掩膜会白贴一大片。
- **可靠判据（按优先级）**：
  1. **射线扫外缘轮廓**：同中心下两图的 `r(θ)` 对比，**中位差 ≈ 0 即无位移**；
     若有系统性位移，则**所有方向同向偏移**（局部几个方向差 ≠ 位移，多半是污染）。
  2. **IoU 平移搜索**（`np.roll` 粗搜 /4 降采样 + 全分辨率精搜）：**只看峰值位置**。
     ⚠️ 注意：这是**"环带颜色掩膜"的 IoU**，而氧化环本身**不是紫的**（紫的是环带上的阳极氧化色块），
     `IoU` 只有 ~0.5，是被"环带颜色掩膜"本身的覆盖范围决定的，**不要因为 IoU 低就断定没对齐**。
  3. 肉眼：紧裁（半宽 ≈ 环半径）对比生成图 vs 成品，看是否出现两条平行边。

### 16.3 收尾自检：掩膜核心区必须逐像素等于原图

- `核心区 = 掩膜向内缩 (2×feather + 安全量)`，此区 alpha≈1，**成品应当就是原图像素**。
- 判据：`mean|成品 − 原图(缩放后)| < 1.0`（本次 0.74 / 0.84，残差来自 JPEG 与 LANCZOS）**且**
  `mean|成品 − 生成图| > 3`（本次 8.26 / 4.73，证明贴回确实生效）。
- 这条自检**不需要读图就能判定**，且能同时抓出"掩膜没生效""坐标填错""角度符号反了"三类错误。



## 17. 生成图长宽比微变：坐标必须分轴换算（2026-09-23 迷雾/微水泥批）

- **现象**：原图 1448:1086 = 1.3333，生成图却是 4800:3584 = 1.3393 —— 模型输出比例与源并不严格一致，横/纵缩放比差 0.45%（3.3149 vs 3.3002）。
- **规则**：先读两张图的实际尺寸，**x、y 各自算缩放比**；`restore_regions.py --match edited` 的语义是把原图**拉伸**到精修图尺寸（`source.resize(edited.size)`），分轴换算的坐标正好与之匹配，不要按单一比例缩放。
- **对齐校验用「灰度图块暴力 pearson 相关」**（源图分轴缩放后取模板，在生成图 ±N px 逐位移算 Pearson），实测环区/字标区/按键区三处漂移全部 ≤2px 即可直接贴回。
- **两个不可信的测量（本次都给出过 +12px 假漂移）**：
  ① **掩膜互相关 / 掩膜外缘圆拟合**——生成环的蓝色像素分布不对称（比原图多且偏一侧），会把 Kåsa 中心和外缘拟合一起带偏；
  ② **自写 FFT 互相关**——归一化与边界处理稍有不慎峰值就顶到搜索边界（三处全部报 +80/+80、+119/+118 这种"贴边值"），一眼要怀疑实现而不是相信结果。
  可靠判据仍是：**图块 Pearson 的峰应落在内部且尖锐**（r≈0.97~0.99、次优解依次衰减），加上回贴后的核心区数值自检兜底。
- **费曼式提醒**：`--feather` 是绝对像素，长宽比变了也不要同比放大（见 §16）；坐标换算与羽化是两件事。


## 18. 接缝无缝化：贴回区影调/纹理与 CGI 周边一致（2026-09-23 迷雾/微水泥批，用户明确要求）

- **接缝的两个来源**：① 低频色差（CGI 调色 vs 原图）；② **纹理差**——原图颗粒 HF 能量与 CGI 可差一倍以上（本次两图方向相反：XaTJ 原图 1.40 vs CGI 0.63，q17p 0.36 vs 1.38）。只做色调匹配，颗粒差照样可见。
- **`--level-match` 不够用**：全局 10/90 分位映射，锚点带若在平坦白墙（q17p 斜率 0.98）等于没做；且一次映射管不了随位置变化的色偏。
- **有效方案＝边界衰减校正**：
  ① 沿掩膜轮廓在外圈 8–20px 测逐点局部均差 D(θ)（环向平滑 σ≈4 点）；
  ② C = D(θ)·exp(−d/λ)，λ≈60px：边界逐点连续、向内衰减回原影调。**不要用扩散/归一化卷积把外圈差值场整体延拓**——外圈差值含结构性成分（模型重画了反光位置），延拓进内部会过校正（实测 v3 阶跃反而 16→19.5）。
- **纹理匹配**：贴回区颗粒比 CGI 糙 → 轻降噪（σ1.2）；比 CGI 光滑 → 补单通道高斯噪声（σ≈1.2）。USM 相应降档（80→60），否则重新放大颗粒。
- **量化验收**：边界阶跃（轮廓逐点 |内带均值−外带均值|，带宽 8px）对比「纯生成区自然对照」；q17p 8.7 < 14.6 ✅；XaTJ 13.3 vs 7.7——**剩余即结构差地板**（模型重画了条带反光），像素域方法到顶，目视已无缝。
- **保真取舍要说清**：影调校正+降噪后贴回区不再是逐像素原图，改用 **pearson≥0.97** 验收字形/位置不变（实测 0.9997/0.9918）。用户要求「色差一致」时这是正确的交换。
