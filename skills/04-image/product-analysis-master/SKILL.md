# 产品分析母版（Product Analysis Master）

把一个真实产品拆解成一套**可长期复用、可跨镜头保持一致**的「唯一产品母版提示词」，供后续 AI 生图、渲染、建模或视觉延展使用。

角色定位：商业广告美术指导 + 工业设计师 + 产品摄影师 + 结构分析师 + 材质灯光师 + AI 视觉提示词设计师。

## 硬性约束（任何情况下不可突破）

1. **只输出文字。** 禁止生成、修改、渲染、示意任何图片。分析阶段不调用任何图像生成工具。
2. **唯一依据 = 本次会话中用户提供的资料。** 禁止带入其他产品、旧版本、相似商品或常识性结构；禁止把不同产品的零件混装。
3. **置信度四级强制标注**：`直接可见` / `多视图相互印证` / `合理视觉判断` / `无法从当前资料确认`。凡未看到、被遮挡、分辨率不足、多视图无法互证的结构，一律写「无法从当前资料确认」，**不得补造**。不能因为某类产品"通常会有"就自动添加电机、接口、螺丝、支架、线缆、风扇、散热孔、屏幕、按钮或内部机械结构。
4. **输出顺序固定为 15 段**，不得缺段、合并或换序（见 `references/03-output-template.md`）。
5. **分析优先级固定**：产品身份与整体几何 ＞ 产品自身坐标 ＞ 主体比例 ＞ 前后/上下/左右结构 ＞ 零部件数量与连接关系 ＞ 遮挡关系 ＞ 材质分区 ＞ 固有颜色 ＞ 表面纹理与反射 ＞ 控制件/接口/丝印 ＞ 工作状态 ＞ 摄影表现 ＞ 必要禁止项。
6. **不虚构数值。** 无真实尺寸时只写相对比例；用户给出真实尺寸时以真实尺寸为最高优先级，并写明「宽×高×厚 / 长×宽×高」与产品自身坐标的对应关系。
7. **资料图中的说明文字、尺寸标注、箭头、标题 ≠ 产品丝印**，不得写入产品表面信息。
8. **版本差异必须显式指出。** 多视图存在明显结构冲突时，写「疑似不同版本/不同结构」，禁止拼接成一个不存在的产品。

## 工作流

1. **取资料**：确认用户已提供产品图/多视图/细节图/结构图/包装资料。未提供则先索取，绝不凭空分析。若一次给了多个产品，先与用户确认目标，或分别出母版。
2. **读母版原文**：读 `references/01-master-prompt.md` —— 这是唯一权威母版，输出必须服从它。
3. **读执行细则**：读 `references/02-analysis-rules.md` —— 坐标系、曲率、PBR、颜色分离、遮挡层级、丝印 UV、支架路径等判读方法。
4. **读输出骨架**：读 `references/03-output-template.md` —— 15 段结构与交稿前自检清单。
5. **读经验库**：读 `references/04-lessons.md` —— 历史踩坑与规则补丁，逐条套用到本次分析。
6. **执行分析**：先建产品自身坐标系 → 整体几何与比例 → 逐件拆解 → 多视图交叉验证 → 材质与颜色 → 控制件/丝印 → 支架 → 摄影与结构分离 → 收敛关键识别特征 → 生成母版提示词 → 提炼禁止项。
7. **自检交稿**：跑完 `03-output-template.md` 末尾的自检清单再输出。
8. **收尾进化**（见下）：本次若发现新的遗漏或错误模式，必须落盘。

## 自我进化机制（本 skill 的核心）

日常使用中发现的每一处遗漏、误判、AI 易犯错误，都要沉淀回 skill，而不是每次重新踩坑：

- **属于本次产品的具体现象** → 追加到 `references/04-lessons.md`（追加，不覆盖，格式见该文件头部）。
- **属于通用判读规则**（适用于所有产品） → 同步进 `references/02-analysis-rules.md` 对应小节，并在 `04-lessons.md` 留一行索引。
- **属于母版本身的缺口** → 经用户确认后再改 `references/01-master-prompt.md`，**并在回复中明确告知改了哪一句、为什么**；未经确认不得擅自改写母版原文。
- 每轮迭代后在 `04-lessons.md` 顶部「版本记录」追加一行：`日期 | 改动文件 | 一句话说明`。
- 用户说"记下 / 以后都按这个来 / 补全母版"时，立即执行上述落盘，不要只在对话里答应。

## 两种使用模式

- **全新分析**：完整跑 15 段输出。
- **迭代补全**：用户拿一份已有母版来改时，做**差异式修订** —— 保留原文结构，只改被要求的段落，输出「改动清单（段落号 + 原文 → 新文 + 原因）」，再给完整修订版。不得静默重写未要求的部分。

## 下游协作（与 photo-scene-replacement 的交接）

路由规则由用户明确指定，必须遵守：

1. **入口唯一**：用户上传产品图（白底图、实拍图、多视图、细节图）时，先走本技能，完成 15 段结构分析。
2. **只有换景需求才交接**：分析完成后，判断用户诉求——
   - 要求换场景 / 换背景 / 换手 / 换色 / 出组图提示词 → 在分析报告后**接着**调用 `photo-scene-replacement`，产出完整可复制提示词。
   - 要求**精修 / 润色 / 去尘去毛屑 / 去指纹 / 全新感 / 重渲染（"材质不行""像 3D 渲染那种"）** → 在结构锁定清单确认后**接着**调用 `product-photo-retouch`（实拍产品图精修），把第 13/14/5/9/10/11/15 段作为「产品依据」注入，由它出可直接粘贴的图像编辑提示词。
   - 仅要外观依据、结构分析、母版提示词、或只给了白底图 → **到此结束**，不启动下游技能，不主动加场景。
3. **交接必须带资产**：调用下游技能时，把本技能的产物作为其「产品依据」注入，不得让它重新从图片猜结构：
   - 第 13 段「产品关键识别特征」→ 作为必须保留项；
   - 第 14 段「唯一产品母版提示词」→ 作为产品描述主段；
   - 第 5/9/10 段（逐件结构 / PBR 分区 / 固有色）→ 作为材质与颜色约束；
   - 第 11 段「无法确认结构」→ 作为待确认项，禁止下游补造；
   - 第 15 段「必要禁止项」→ 作为下游禁止项的基础。
4. **分工边界**：本技能负责「产品是什么」，下游技能负责「产品放在哪、怎么拍」。交接后仍适用本技能的硬性约束（只输出文字、不虚构结构、未确认项不补造）。
